## Reading it

- **2026-11b's causes mostly don't come up here.** No use touches mcp 2's `mcp.types` or a module dunder. The uses
  that do touch earlier misses are read right: langchain-community's 19 working uses, mcp 1.10 → 2.3's 14 working
  uses and 18 breaks, and transformers 5's 45 working uses. So this set says little about DT-DATA-56 or DT-CORE-38,
  and its false positives are new causes.
- `check_symbols`'s 9 false positives have three causes, all in two upgrades:
  - **pydantic 2 serves v1's `pydantic.error_wrappers.ValidationError`** through `getattr_migration` (the `MOVED_IN_V2`
    table in `pydantic/_migration.py`), with a warning. The index sees only the module's `__getattr__`, so the name
    reads missing after 1.10.27 (4: the name and a call, in two upgrades). `diff_versions` reports the same 4 as
    removed.
  - **`pydantic.networks.IPv4Address` reads "never seen".** pydantic's `networks` imports it from the standard
    library's `ipaddress` in every release, and the index doesn't record imports from the standard library (4).
  - **openai 3.46's `openai.ChatCompletion.create`** (1). openai 1.x and later keep `ChatCompletion` as a proxy, so that
    reading its attributes still works; calling it raises `APIRemovedInV1`. DepTime's `missing`, with
    `Completions.create` to try, is the useful answer. The rules label the use `works` because the name resolves.
- `diff_versions`'s 6 false positives:
  - the same `error_wrappers.ValidationError` (4);
  - `langgraph.prebuilt`, reported removed in 0.3.1, though langgraph 1.x requires the `langgraph-prebuilt`
    distribution, which installs it into the namespace (`check_symbols` answers `unknown`);
  - `StateGraph(State)`, where the pre-registered rule counts a newly required parameter the call passes positionally
    (as on 2026-11 and 2026-11b).
- **The one missed break, by both tools:** polars 1.9 code run on 0.19.6. `pl.int_range(n)` fails there, because `end`
  is required. From 0.19.1, the index reads `polars.int_range` as the module `polars.functions.range.int_range`, not as
  the function that module defines and its package re-exports, so it has no signature to check.
  - 17 polars paths read this way, among them `col`, `lit`, `len`, `repeat` and `date_range`, so `check_symbols` can't
    check their keywords.
  - Nine paths in other packages have the same shape, still to be checked one by one.
- **Abstentions:** `check_symbols` answers `unknown` for 40 working uses and 4 breaks.
  - The 4 breaks are `langgraph.prebuilt.create_agent_executor` and llama-index 0.12's `ReActAgent.from_tools`, each
    asked twice. The first is behind the same namespace package; the second inherits from the `workflows`
    distribution.
  - `diff_versions` gets `create_agent_executor` from the removal of `langgraph.prebuilt`, the same event that gives it
    the false positive above.
- **Deprecations** mark 24 working uses. `check_symbols` flags 23 as deprecated, 22 of them among those 24 (recall
  91.7%; 74.2–97.7). `diff_versions` flags 23, 19 of them (79.2%).
- **Tracebacks:** the four misses have four different causes.
  - langgraph 0.0.21's `compile(interrupt_before=...)`: `Graph.compile` and `StateGraph.compile` both gained the
    parameter in 0.0.24, and the error names `compile()` without its class. DepTime lists both, with the same versions
    and pin, and says it can't tell. The scorer takes the first, `Graph`, so the pin is right and the name a coin toss
    (DT-CORE-31's case, as polars' `sort`).
  - langchain 1.0's `MultiQueryRetriever.get_relevant_documents`. The class is langchain-classic's, which isn't
    indexed, and the method was langchain-core's `BaseRetriever`'s, removed in 1.0.0. DepTime names
    `langchain.schema.BaseRetriever.get_relevant_documents`, a path langchain dropped after 0.0.340, over
    langchain-core's removal at the installed release.
  - scikit-learn 1.7's `BaseEstimator._validate_data`, called by gplearn's subclass: no finding. The index has the
    private method, until 1.6.1, among its internal members, but `explain_error` looks only at public members for a
    class it doesn't know.
  - pytest 9.1's `_pytest._code.code.FormattedExcinfo`, imported by the tavern plugin: `_pytest` is indexed for
    `_pytest.hookspec` alone.
- **Replacement** (4/8): two misses are the unanswered tracebacks above. The other two:
  - pandas' `fillna(method)`, whose warning says "Use obj.ffill() or obj.bfill() instead": the receiver is written
    `obj.`, which the miner doesn't read.
  - fastmcp 4's removed `fastmcp.server.apps`, whose names were re-exports of `fastmcp.apps` from 3.2.0: the moved
    heuristic pairs names, not modules.
