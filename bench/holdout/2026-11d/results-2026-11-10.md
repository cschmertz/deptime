## Reading it

- **2026-11c's causes don't come back.** No pydantic `getattr_migration` name, polars re-exported function or name
  imported from the standard library reads wrong. In the exercise stratum, both tools read DT-DATA-56's `mcp.types`
  (14 uses) and DT-CORE-39's crewai calls (7) right; of DT-CORE-38's 12 module dunders, `check_symbols` reads 8 right,
  answers `unknown` for 3 and gets `pandas.__version__` wrong (below).
- **One upgrade gives 15 false positives per tool:** dspy 2.6 code asked about dspy 0.1.5, a year older. dspy 0.0.1 to
  0.1.5 on PyPI are placeholder releases ("Placeholder package for DSPy") that ship no `dspy` module and require
  `dspy-ai==2.4.5`, which provides it. The index reads them as empty, so every name reads missing at 0.1.5 (answered at
  0.1.4, the nearest indexed release) and added after it.
- `check_symbols`' other 5:
  - chromadb 0.6.3's `utils.embedding_functions.SentenceTransformerEmbeddingFunction` (2, and the same 2 for
    `diff_versions`): from 0.5 the package's `__init__` imports each submodule and writes its embedding-function
    classes into `globals()`, names the index can't see statically.
  - polars 1.6's `polars.ComputeError`: polars 1.x serves every exception at the top level through a module
    `__getattr__` that tests `name in dir(exceptions)` and warns, until 2.0 removes it. The index reads the name gone
    after 0.20.31 (and so `diff_versions` misses its real removal in 2.0, below).
  - `pandas.__version__` at 2.1.1 (the exercise stratum): pandas 2.x imports it from the private `pandas._version_meson`
    in a `try`, which the index doesn't record, and DT-CORE-38 reads a dunder another release has (3.1) as `missing`.
  - huggingface_hub 0.12.1's top-level `_CACHED_NO_EXIST`: served from the lazy-import table `_SUBMOD_ATTRS` until 0.28,
    and the index records only the table's public names there.
- **Missed breaks:**
  - llama-index-core 0.14's `ServiceContext.from_defaults` (3 uses, both tools): a classmethod taking `**kwargs` whose
    body only raises "ServiceContext is deprecated". The probe labels calls to an object built to fail as breaks (new in
    this set); the index sees a function.
  - huggingface_hub's top-level `list_models(model_name=)` and `upload_folder(run_as_future=)` (3 uses, both tools):
    the package binds them as `list_models = api.list_models` on a module-level `HfApi()`, which the index stores as an
    attribute with no signature, so the keyword isn't checked, though `HfApi.list_models` rejects it.
  - `diff_versions` alone: langchain 0.0.109's private `SQLDatabase._get_sample_rows` (not yet added) and flask 3's
    `_app_ctx_stack` (removed), names that aren't public API, which `check_symbols` answers from the index's internal
    rows and `diff_versions` doesn't report; and polars 2.0's `ComputeError`, above.
- **Abstentions:** `check_symbols` answers `unknown` for 55 working uses (sqlmodel 16, langgraph 12, pytest 10,
  streamlit 8, ...) and 2 breaks, fastmcp's `prompts.prompt.Message` and `tools.tool.ToolResult`, where the module
  became a function of the same name; `diff_versions` finds both.
- **Deprecations** mark 11 working uses. `check_symbols` flags 11 as deprecated, 9 of them among those 11 (recall 81.8%;
  52.3–94.9). `diff_versions` flags 16, the same 9.
- **Tracebacks:** the four misses have four causes, and none is a wrong answer (precision 96.3%: the one wrong finding is
  urllib3's).
  - fastmcp 3's `FastMCP(log_level=)`: the error is fastmcp's own "FastMCP() no longer accepts `log_level`. Pass
    `log_level` to `run_http_async()` ...", a message shape the parser doesn't read.
  - polars 2.0's `DataFrame._from_arrow(rechunk=)`: the index has the private method, but its internal rows store no
    parameters.
  - pytest 8's `CallSpec2.funcargs`: `_pytest` is indexed for its module-level names (DT-DATA-62), not the members of
    its classes.
  - urllib3 2's `Retry.DEFAULT_METHOD_WHITELIST`, read "never existed": in 1.26 it is a property of the metaclass
    `_RetryMeta`, which the index records on the metaclass, not on `Retry`.
- **Replacement** (8/17): two misses are the unanswered tracebacks above (fastmcp, urllib3). The other seven:
  - langchain 1.0's `chains` and `initialize_agent` (2): their home is the `langchain-classic` distribution, which isn't
    covered.
  - huggingface_hub 0.25's private `utils._errors` (2): its classes moved to `huggingface_hub.errors`, and nothing pairs
    a private module with its classes' new home.
  - gradio 4's `Box`: 3.x warns "gr.Box is deprecated. Use gr.Group instead." in `__init__`'s body, which the miner
    doesn't read (the docstring's "DEPRECATED" names no replacement).
  - streamlit 1.37's `experimental_data_editor`: no deprecation is mined for the renaming wrapper bound to the old name.
  - numpy 2.4's `percentile(interpolation=)`: the docstring's "Deprecated name for the method keyword argument" isn't
