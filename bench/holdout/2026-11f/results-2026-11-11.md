## Reading it

- **2026-11e's causes don't come back.** No call passes too many positional arguments, litellm's calls into `**kwargs`
  aren't flagged (the scorer's `absorbed_by_var_keyword` rule), and `check_symbols` reads every class deprecated in its
  own `__init__` (DT-CORE-53). Of 2026-11e's misses run again on today's code (a check, not a score), 27 of 28
  tracebacks pass and both tools find all 140 breaks.
- **Both tools' two false positives** are one scikit-learn 1.2.2 → 1.9.1 import, `from sklearn.tree._tree import
  TREE_LEAF`. `sklearn.tree._tree` is a compiled (Cython) module, which the index can't read without importing it, so
  no release has it: `check_symbols` reads both uses missing, "never seen in any indexed release", and `diff_versions`
  lists them in `never_seen` (DT-CORE-54).
- **Missed breaks** (`diff_versions`, 5; `check_symbols` abstains on the same 5):
  - fastmcp 2.10.1 → 4.1.8's `from fastmcp.prompts.prompt import PromptMessage, TextContent` (4 uses). fastmcp 3.0
    dropped the module, and `fastmcp.prompts.prompt` is now the `prompt` decorator, so the import fails.
    `diff_versions` returns the right event (`kind_changed`, module to function, at 3.0.0, with both names in
    `affects`), but the rule counts only events that remove the name; `check_symbols` answers `unknown` ("a function,
    not a module or class, so the index doesn't list" the names under it).
  - langgraph 1.0.2 → 0.2.39's `checkpoint.base.get_checkpoint_metadata`: at 0.2.39 the module comes from the
    `langgraph-checkpoint` distribution. `check_symbols` answers `unknown`, naming it; `diff_versions` returns no event
    and no note, which reads as nothing changed.
- **Abstentions:** `check_symbols` answers `unknown` for 66 working uses and the 5 breaks above.
- **Deprecations** mark 18 working uses. `check_symbols` flags 16 of them (recall 88.9%; 67.2–96.9) and 2 more that
  are calls with a parameter it reads deprecated (scikit-learn's `DecisionTreeRegressor(...)`, fastmcp's
  `RateLimitingMiddleware(...)`), which the probe's rule, about the name, doesn't cover. Its two misses are
  langchain-community 0.4.2's `llms.OpenAI` (a name and a call): `llms` serves it from a lazy table, and the index has
  the deprecation on `llms.openai.OpenAI` only. `diff_versions` flags 12 of the 18 (66.7%): besides `llms.OpenAI`, it
  says nothing of a deprecation in force at both ends (langgraph 1.0.2 → 1.2.20's `errors.NodeInterrupt`, deprecated
  since 0.6; huggingface_hub's `Repository` going down), and it flags gradio 3.x → 6.31.0's `gr.update` from its 3.45
  deprecation, which 3.48 dropped.
- **Tracebacks:** six misses, one of them a wrong finding (precision 95.2%).
  - Four are the way a page pastes the error, which the parser doesn't read:
    - mcp: "got an unexpected keyword argument \`description\`", the keyword in backticks;
    - django: "cannot import name 'smart_text' from" with the module on the next line and its opening quote lost;
    - selenium: "WebDriver.init()", Markdown having eaten `__init__`'s underscores;
    - redis: a traceback with its exception lines first, whose last exception is Django's `import_string` message,
      'Module "redis.connection" does not define a "HiredisParser" attribute/class'.

    Pasted as Python prints them, django's and redis's pass (django's with `smart_str`). selenium's finds
    `ie.webdriver.WebDriver.__init__(service_log_path)`, the right release for the wrong browser: ie's `WebDriver`
    dropped it in the same release, and the line names no browser. mcp's reads `never_existed`, as the next miss.
  - mcp 1.12.3's `FastMCP(description=)`: `description` was never a named parameter. 1.12.2's `FastMCP.__init__`
    took it, and ignored it, through `**settings`, which 1.12.3 removed. The index has that removal, but
    `explain_error` answers the keyword `never_existed`.
  - huggingface_hub 1.0's `hf_hub_download(use_auth_token=)`, the wrong finding: `never_existed` at medium. Up to 0.36
    the `validate_hf_hub_args` decorator took `use_auth_token` and passed it on as `token`, so the function's own
    signature in the indexed releases never listed it; 1.0 dropped that.
  - transformers 4.49's `_extract_past_from_model_output`: the error names the project's own model class
    (`'CogVLMForCausalLM' object has no attribute ...`), which subclasses transformers' `GenerationMixin`; the frames
    above it are transformers' `generation/utils.py`.
- **Replacement** (5/13): two of the misses are the django and huggingface_hub tracebacks above. The other six:
  - openai 1.0's `Embedding` and `Image`: DepTime names `openai.types.Embedding` and `openai.types.Image`, the
    response types that share the name, where the migration guide says `client.embeddings.create()` and
    `client.images.generate()`. A wrong replacement is worse than none.
  - fastmcp 3's `include_tags`: 3.x keeps a `_REMOVED_KWARGS` table mapping each removed keyword to its message
    ("Use \`server.enable(tags=..., only=True)\` after creating the server"), which the index doesn't read.
  - scikit-learn 1.3's `neighbors.DistanceMetric`: `metrics.DistanceMetric` has had it since 1.2, but as an alias into
    a compiled module (`metrics._dist_metrics`), which the index can't follow, so no rule has a class there to pair.
  - sqlalchemy 2.0's `databases` module: 1.4's warns when imported, "Use the \`dialects\` package instead", which the
    index doesn't read as the module's deprecation.
  - gradio 3.24's `processing_utils.encode_url_or_file_to_base64`: its home is `gradio_client.utils`, in a distribution
    that isn't covered.
